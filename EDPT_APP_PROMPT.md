# Build Prompt: All-In-One EDPT Trainer App

Copy everything below the line into Claude Code (or any coding agent) to build the app.

---

You are a senior full-stack engineer and test-prep curriculum designer. Build a complete, production-quality study application for the **EDPT (Electronic Data Processing Test)**, the U.S. Air Force aptitude exam used to qualify airmen and officers for cyber and programming career fields (for example 1D7X1 Cyber Defense Operations, 1B4X1 Cyber Warfare Operations, and 17S/17D cyber officers). The app must take a user from zero knowledge to test-day readiness without needing any other resource.

## 1. What the EDPT is (ground truth for the app)

Encode the following as the app's reference content. Where exact policy numbers are uncertain, make them configurable constants with a visible "verify with your recruiter / MPF" note rather than hard-coding a guess.

- Roughly 120 multiple-choice questions in about 90 minutes, which is around 45 seconds per question. Pacing is the hardest part of the test.
- Question types, all of which the app must teach, generate, and drill:
  1. **Number sequences**: find the next term or the missing term (arithmetic, geometric, alternating, second-order differences, interleaved sequences, primes, squares, Fibonacci-style, operations that change by position).
  2. **Letter sequences**: alphabet position arithmetic, skipping patterns, alternating forward/backward, paired letters, wraparound.
  3. **Figure/pattern sequences and analogies**: shapes that rotate, flip, add/remove elements, change shading, change count, or combine rules; "A is to B as C is to ?" with figures; odd-one-out.
  4. **Arithmetic reasoning / word problems**: rates, ratios, percentages, averages, unit conversion, time and distance, work problems, simple algebra, done under time pressure with no calculator.
  5. **Logical reasoning**: syllogisms, deductive chains, if-then rules, ordering and seating puzzles, set membership, true/false/cannot-be-determined.
  6. **Reading comprehension / verbal analogies**: short passages with inference questions, and word analogies.
- No calculator. Scratch paper is allowed. Build a scratch-pad feature to simulate this.
- Minimum qualifying scores differ by career field (commonly cited around 71 for cyber AFSCs). Store these as an editable table with a disclaimer.
- Retest rules exist (a waiting period before retaking). Store as editable reference text with a disclaimer.

Do **not** reproduce or imitate any real, leaked, or copyrighted EDPT items. All questions must be originally generated by the app's own generators or written fresh in the app's style.

## 2. Core features (all required)

### Learn
- A structured course with one module per question type: concept explanation, worked examples, common traps, a "how to spot the pattern in 10 seconds" checklist, and a short mastery check before unlocking the next difficulty tier.
- A test-strategy module: pacing plan, when to skip, elimination tactics, mental-math shortcuts, how to read figures quickly, test-day logistics, and a guessing-strategy section that adapts to the configured scoring model (penalty vs. no penalty).
- Mental-math drills: multiplication tables, percentages, fractions-to-decimals, squares and cubes, estimation, all timed.

### Practice
- **Procedural question generators** for every question type so the bank is effectively infinite. Each generator must:
  - produce the question, exactly one correct answer, 3 to 4 plausible distractors built from likely mistakes (off-by-one, wrong operation, sign error, reversed rule),
  - produce a step-by-step explanation that names the rule,
  - accept a difficulty parameter (1 to 5) that controls rule complexity, number size, and distractor similarity,
  - be seeded so any question can be reproduced from its ID.
- Figure questions must render as generated SVG (shapes, rotations, shading, counts), not static images.
- Practice modes: untimed with instant feedback, timed per question, section drills, mixed drills, "weak areas only", and "review mistakes".
- Spaced repetition: missed questions and weak rules come back on a schedule (SM-2 or similar).

### Simulate
- Full-length timed exams matching real format: question count, total time, section mix, no backtracking option (toggleable), on-screen scratch pad, flag-for-review, and a countdown that mimics real conditions.
- Half-length and quarter-length versions.
- End-of-exam report: raw score, estimated scaled score band (clearly labelled as an estimate), per-section accuracy, time per question, questions where the user was right but slow, and a list of the rules missed.

### Analyze
- Dashboard with trend lines for accuracy, speed, and estimated score over time.
- Per-rule heatmap (for example "second-order differences: 55%, 38s avg").
- A readiness indicator that combines accuracy and pacing against the user's target career field cutoff.
- Study-plan generator: given a test date and minutes per day, build a daily plan and adjust it as results come in.

### Account and data
- Local-first: all progress works offline and persists on device. Optional account sync is a bonus, not required for v1.
- Export and import progress as JSON.
- Settings: target AFSC, test date, daily goal, scoring model, dark mode, font size, reduced motion.

## 3. Technical requirements

- Stack: TypeScript, React (Next.js or Vite), Tailwind, installable PWA so it runs on phone and desktop. State in a local database (IndexedDB via Dexie or similar). If you choose a backend, keep it optional.
- Clean architecture: `generators/` (pure functions, one file per question type, fully unit-tested), `engine/` (session, timer, scoring, spaced repetition), `content/` (lessons as MDX or structured JSON), `ui/`.
- Tests: unit tests for every generator (correct answer is unique, distractors never equal the answer, same seed gives same question, every difficulty level produces valid output), plus tests for scoring and the spaced-repetition scheduler.
- Accessibility: keyboard-only operation, screen-reader labels on figures (describe the pattern without giving away the answer), WCAG AA contrast.
- Performance: question generation under 50 ms, no layout shift during timed sessions.
- Mobile-first layout; the timed exam must be usable on a phone.

## 4. Content quality bar

- Every question type must ship with at least 10 distinct rule families, each at 5 difficulty levels.
- Explanations teach the rule, not just the answer. Format: "Pattern: ... / How to spot it: ... / Trap: ...".
- Lessons are written for a motivated adult with high-school math, in plain language.
- Include a glossary and a "rule library" the user can browse.

## 5. Deliverables and workflow

1. Start with a short written plan: architecture, data model, and a list of the generators with their rule families. Then build.
2. Work in vertical slices: get one question type end-to-end (generator, tests, practice UI, explanation) before adding the next.
3. Commit after each slice with descriptive messages. Keep the app runnable at every commit.
4. Finish with a README covering setup, how to add a new rule family, how to adjust scoring constants, and the disclaimer that this is an unofficial study tool not affiliated with the U.S. Air Force.
5. Before declaring done, run the full test suite and a complete simulated exam in the browser and fix anything that breaks.

If a requirement is ambiguous, pick the option that most closely mimics the real testing experience and note the assumption in the README.
